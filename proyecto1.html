Walkthrough: Vulneración y Auditoría de Seguridad

Ejercicio práctico de Análisis de Vulnerabilidades, Explotación y Escalada de Privilegios.

1. Introducción y Objetivos del Proyecto

El presente proyecto consiste en la resolución metódica y documentada (Walkthrough) de un entorno controlado vulnerable de ciberseguridad. El objetivo principal es identificar, explotar y mitigar fallos de seguridad dentro del sistema objetivo, aplicando buenas prácticas de seguridad ofensiva (Red Teaming) y defensa (Blue Teaming).

Objetivos Específicos:

  • Identificar puertos abiertos, servicios activos y versiones vulnerables mediante reconocimiento activo.
  • Descubrir y analizar vectores de entrada para obtener un acceso inicial al sistema.
  • Realizar un proceso metódico de escalada de privilegios hasta alcanzar acceso de administrador/root.
  • Proponer recomendaciones técnicas detalladas para solucionar las vulnerabilidades encontradas.

2. Fase de Reconocimiento y Escaneo

Se inició el análisis aplicando la metodología de reconocimiento de red para determinar el alcance del objetivo e identificar posibles puertos de entrada.

Comandos ejecutados (Nmap):

# Escaneo rápido de puertos abiertos
nmap -p- --open -sS --min-rate 5000 -n -pn 10.10.10.X -oN target_ports.txt

# Escaneo detallado de versión y scripts por defecto
nmap -sCV -p 22,80,443 10.10.10.X -oN target_services.txt

Resultados del Escaneo:

Puerto Estado Servicio Versión / Detalle
22/TCP Abierto SSH OpenSSH 8.2p1
80/TCP Abierto HTTP Apache httpd 2.4.41
443/TCP Abierto HTTPS Apache (Certificado SSL autofirmado)

3. Enumeración Web y Explotación Inicial

Al inspeccionar el servicio HTTP en el puerto 80, se procedió con la enumeración de directorios ocultos utilizando la herramienta gobuster / ffuf. 

gobuster dir -u http://10.10.10.X/ -w /usr/share/wordlists/dirb/common.txt -x php,html,txt

Se descubrió la ruta /admin/upload.php, la cual contenía un formulario de carga de archivos con validación insuficiente en el lado del servidor.

Vulnerabilidad identificada: Inyección / Arbitrary File Upload. La aplicación no filtraba adecuadamente las extensiones .php, permitiendo la carga de código arbitrario.

Se preparó un payload en PHP para establecer una conexión en reversa (Reverse Shell) hacia nuestra máquina atacante: 

# Escucha en la máquina atacante
nc -nlvp 4444

Tras ejecutar la petición con el archivo malicioso, se logró el primer acceso al sistema remoto bajo el contexto del usuario sin privilegios www-data.

4. Escalada de Privilegios

Con acceso inicial al sistema, se realizó una enumeración local para identificar configuraciones erróneas, tareas programadas (cron jobs) o binarios con permisos SUID. 

# Búsqueda de binarios con bit SUID activo
find / -perm -4000 -type f 2>/dev/null

Se detectó una tarea programada administrada por el usuario root que ejecutaba un script con permisos de escritura modificables por el grupo del usuario actual. Modificando el script e incluyendo una instrucción para otorgar permisos SUID a la terminal /bin/bash, se obtuvo acceso completo como superusuario. 

# Acceso root conseguido
whoami
# Output: root

5. Conclusiones y Recomendaciones Técnicas

Para corregir las brechas encontradas y mejorar la postura de seguridad de la infraestructura, se sugieren las siguientes acciones remediadoras:

Mitigación de Sanitización

  • Validar extensiones de archivos subidos utilizando listas blancas (Whitelist).
  • Almacenar archivos subidos fuera del directorio raíz web y deshabilitar la ejecución de scripts en esa ruta.

Mitigación de Privilegios

  • Aplicar el principio de menor privilegio (Principle of Least Privilege).
  • Restringir los permisos de escritura en scripts del sistema ejecutados por el usuario root.
