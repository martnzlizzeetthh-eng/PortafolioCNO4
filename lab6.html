File Path Traversal - Validation of File Extension with Null Byte Bypass

Laboratorio Práctico de PortSwigger Web Security Academy

01. Marco Teórico y Fundamentación Técnica

File Path Traversal con Inyección de Null Byte (%00) es una técnica de evasión empleada en aplicaciones donde el servidor valida que el nombre del archivo termine con una extensión permitida (por ejemplo, .png o .jpg) antes de cargarlo.

Mecanismo de la Vulnerabilidad

En lenguajes de programación basados en C/C++ (o envoltorios del sistema de archivos de bajo nivel), el carácter byte nulo (0x00 o %00 en formato URL) se utiliza como un delimitador de fin de cadena (null terminator).

Cuando la aplicación web procesa la entrada, la validación de alto nivel comprueba la cadena completa y confirma que finaliza en .jpg. Sin embargo, al pasar la cadena a las funciones de lectura de archivos del sistema operativo, el proceso se interrumpe inmediatamente al llegar al %00, ignorando la extensión posterior y leyendo la ruta inyectada.

Impacto (Triada CIA y OWASP)

  • A01:2021 - Broken Access Control (OWASP Top 10): Evasión de la validación de extensiones permitidas mediante discrepancias en la interpretación del fin de cadena.
  • Confidencialidad: Extracción de archivos sensibles como /etc/passwd anulando la comprobación obligatoria de formato de imagen.
  • Principio de Defensa: Utilizar APIs modernas de gestión de archivos que no dependan del carácter nulo como terminador y validar el tipo MIME real mediante inspección de contenido (magia de bytes) en lugar de la extensión solicitada.

02. Procedimiento Técnico y Uso de Burp Suite

A continuación se detalla el procedimiento paso a paso para identificar y explotar el bypass por Null Byte:

  1. Intercepción de Petición: Se navega en el sitio e intercepta con Burp Proxy la solicitud GET que carga las imágenes de los productos.
  2. Transferencia a Repeater: Se reenvía la petición GET /image?filename=... a Burp Repeater (Ctrl + R).
  3. Análisis del Control de Extensión: Al intentar inyectar ../../../etc/passwd, la aplicación rechaza la solicitud indicando que el archivo debe terminar en una extensión válida de imagen (ej. .png o .jpg).
  4. Inyección del Payload con Null Byte: Se construye el payload agregando el carácter nulo codificado en URL antes de la extensión requerida:
    ../../../etc/passwd%00.jpg.
  5. Confirmación de Explotación: La aplicación aprueba la solicitud porque termina en .jpg, pero la llamada al sistema de archivos se trunca en /etc/passwd, devolviendo el contenido del archivo con código de respuesta 200 OK.

03. Documentación Técnica del Laboratorio

Lab: File path traversal, validation of file extension with null byte bypass

URL del Laboratorio: PortSwigger Web Security Academy - Null Byte Bypass

Alteración de la Petición HTTP:

-- Petición Original:
GET /image?filename=34.jpg HTTP/1.1
Host: lab-id.web-security-academy.net

-- Petición Alterada con Payload (Null Byte Injection):
GET /image?filename=../../../etc/passwd%00.jpg HTTP/1.1
Host: lab-id.web-security-academy.net

Explicación Técnica del Payload:

Payload: ../../../etc/passwd%00.jpg
La validación de la aplicación revisa que la cadena termine con la extensión esperada (.jpg). Como esta regla se satisface, la petición es aprobada. Sin embargo, al enviarse al sistema de archivos del servidor, la secuencia de bytes se trunca en el Byte Nulo (%00), provocando que la operación abra y lea únicamente el archivo /etc/passwd.
