File Path Traversal - Traversal Sequences Stripped with Superfluous URL-decode

Laboratorio Práctico de PortSwigger Web Security Academy

01. Marco Teórico y Fundamentación Técnica

File Path Traversal con Doble Codificación URL (Superfluous URL-decode) es una vulnerabilidad provocada por el orden incorrecto en el procesamiento de entradas en el servidor. Ocurre cuando una aplicación realiza la validación/sanitización de seguridad antes de decodificar completamente la entrada del usuario.

Mecanismo de la Vulnerabilidad

El servidor de aplicaciones o firewall inspecciona el parámetro de entrada buscando secuencias maliciosas como ../. Si los caracteres están codificados doblemente mediante URL encoding (por ejemplo, codificando el caracter % como %25), el filtro de seguridad ve una cadena supuestamente inofensiva como %252e%252e%252f y la permite.

Posteriormente, cuando la solicitud pasa a la capa de procesamiento del backend o la función de lectura de archivos, el servidor aplica un proceso redundante de decodificación URL (superfluous URL-decode), convirtiendo %252e%252e%252f primero en %2e%2e%2f y finalmente en ../, ejecutando el traversal exitosamente.

Impacto (Triada CIA y OWASP)

  • A01:2021 - Broken Access Control (OWASP Top 10): Bypass del filtro perimetral debido a una incoherencia en las fases de decodificación de datos.
  • Confidencialidad: Lectura de archivos críticos del sistema (/etc/passwd) al evadir los controles de seguridad mediante encoding.
  • Principio de Defensa: Decodificar las entradas del usuario una sola vez antes de cualquier validación, o utilizar funciones nativas del sistema que resuelvan la ruta canónica asegurando que permanezca dentro de los límites autorizados.

02. Procedimiento Técnico y Uso de Burp Suite

A continuación se detalla el procedimiento paso a paso para identificar y explotar el bypass de decodificación URL redundante:

  1. Intercepción de Petición: Se navega en la tienda objetivo y se intercepta la petición HTTP enviada para cargar la imagen de un producto con Burp Proxy.
  2. Transferencia a Repeater: Se envía la petición GET /image?filename=... a Burp Repeater (Ctrl + R).
  3. Prueba de Traversal Directo (Bloqueado): La inyección de ../../../etc/passwd o la codificación simple (%2e%2e%2f) falla, ya que la aplicación detecta o bloquea los patrones de traversal.
  4. Inyección del Payload con Doble Codificación: Se codifica doblemente la secuencia de retroceso:
    • . = %2e → %252e
    • / = %2f → %252f
    Formando el payload: %252e%252e%252f%252e%252e%252f%252e%252e%252fetc/passwd.
  5. Confirmación de Explotación: Al enviar la petición modificada, la aplicación decodifica los valores internamente en dos etapas, interpretando la ruta real ../../../etc/passwd y devolviendo el contenido del archivo con un estado 200 OK.

03. Documentación Técnica del Laboratorio

Lab: File path traversal, traversal sequences stripped with superfluous URL-decode

URL del Laboratorio: PortSwigger Web Security Academy - Superfluous URL-decode

Alteración de la Petición HTTP:

-- Petición Original:
GET /image?filename=60.jpg HTTP/1.1
Host: lab-id.web-security-academy.net

-- Petición Alterada con Payload (Doble URL Encoding):
GET /image?filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc/passwd HTTP/1.1
Host: lab-id.web-security-academy.net

Explicación Técnica del Payload:

Payload: %252e%252e%252f%252e%252e%252f%252e%252e%252fetc/passwd
Al enviar %252e%252e%252f, el filtro inicial de la aplicación solo decodifica el primer nivel de encoding, convirtiéndolo en %2e%2e%2f. Como este string no coincide directamente con la cadena literal ../, supera la validación de seguridad. Posteriormente, el componente interno del servidor realiza una segunda decodificación (superfluous URL-decode), transformando la entrada en ../ y permitiendo el acceso al archivo /etc/passwd.
