File Path Traversal - Validation of Start of Path

Laboratorio Práctico de PortSwigger Web Security Academy

01. Marco Teórico y Fundamentación Técnica

File Path Traversal con Validación del Inicio de la Ruta ocurre cuando una aplicación intenta mitigar ataques de salto de directorio verificando estricta y únicamente que el parámetro suministrado comience con una ruta prefijada autorizada (por ejemplo, /var/www/images/).

Mecanismo de la Vulnerabilidad

La falla radica en asumir que porque la entrada inicia con la ruta esperada, el acceso está restringido a esa carpeta. El filtro no valida lo que ocurre en el resto de la cadena.

Un atacante puede cumplir la condición requerida incluyendo la ruta inicial requerida y agregando inmediatamente secuencias de retroceso ../. De esta forma, se satisface la comprobación de prefijo, pero el sistema operativo navega hacia afuera del directorio restringido para acceder a cualquier archivo del sistema.

Impacto (Triada CIA y OWASP)

  • A01:2021 - Broken Access Control (OWASP Top 10): Control de acceso deficiente basado en validaciones superficiales de la estructura de la URL.
  • Confidencialidad: Acceso no autorizado a archivos sensibles del servidor web (/etc/passwd) mediante la evasión del prefijo obligatorio.
  • Principio de Defensa: No confiar en comprobaciones simples de inicio de cadena. Se debe resolver la ruta canónica absoluta mediante funciones del lenguaje y verificar que el directorio base resultante sea estrictamente el permitido.

02. Procedimiento Técnico y Uso de Burp Suite

A continuación se detalla el procedimiento paso a paso para identificar y explotar el bypass de la validación del inicio de ruta:

  1. Intercepción de Petición: Se explora el sitio web e intercepta con Burp Proxy la solicitud GET utilizada para cargar la imagen de un producto.
  2. Transferencia a Repeater: Se reenvía la petición GET /image?filename=/var/www/images/... a Burp Repeater (Ctrl + R).
  3. Análisis de la Validación: Se observa que el parámetro filename incluye la ruta absoluta completa donde se alojan las imágenes (por ejemplo, /var/www/images/50.jpg). Si se intenta reemplazar toda la ruta por ../../../etc/passwd, la aplicación devuelve un error al fallar la validación inicial.
  4. Inyección del Payload con Prefijo Válido: Se mantiene la ruta base requerida al inicio y se concatenan las secuencias de navegación hacia el directorio raíz:
    /var/www/images/../../../etc/passwd.
  5. Confirmación de Explotación: La aplicación valida que la cadena comience por /var/www/images/, aprueba la solicitud y el sistema de archivos procesa las secuencias ../, devolviendo el contenido del archivo /etc/passwd con un estado HTTP 200 OK.

03. Documentación Técnica del Laboratorio

Lab: File path traversal, validation of start of path

URL del Laboratorio: PortSwigger Web Security Academy - Validate Start of Path

Alteración de la Petición HTTP:

-- Petición Original:
GET /image?filename=/var/www/images/28.jpg HTTP/1.1
Host: lab-id.web-security-academy.net

-- Petición Alterada con Payload (Mantenimiento del Prefijo):
GET /image?filename=/var/www/images/../../../etc/passwd HTTP/1.1
Host: lab-id.web-security-academy.net

Explicación Técnica del Payload:

Payload: /var/www/images/../../../etc/passwd
El filtro de validación revisa únicamente si el valor del parámetro comienza con el directorio esperado (/var/www/images/). Como la condición se cumple, la entrada se envía al sistema de archivos donde los tres niveles de ../ retroceden desde /var/www/images/ hasta el directorio raíz (/), permitiendo la lectura directa de /etc/passwd.
