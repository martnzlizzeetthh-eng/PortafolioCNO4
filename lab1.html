File Path Traversal - Simple Case

Laboratorio Práctico de PortSwigger Web Security Academy

01. Marco Teórico y Fundamentación Técnica

File Path Traversal (también conocido como Directory Traversal) es una vulnerabilidad de seguridad web que permite a un atacante leer archivos arbitrarios almacenados en el sistema de archivos del servidor donde se ejecuta la aplicación.

Mecanismo de la Vulnerabilidad

Ocurre cuando una aplicación web utiliza parámetros proporcionados por el usuario para construir rutas a archivos locales en el servidor (como imágenes o documentos) sin la debida sanitización o validación por lista blanca.

Mediante secuencias de escape de directorios como ../ (dot-dot-slash), el atacante puede navegar hacia arriba en el árbol de directorios del sistema operativo hasta alcanzar la raíz (/) y acceder a archivos sensibles del sistema como /etc/passwd.

Impacto (Triada CIA y OWASP)

  • A01:2021 - Broken Access Control (OWASP Top 10): Falla directa en el control de acceso a recursos del sistema de archivos.
  • Confidencialidad: Pérdida crítica al exponer código fuente, credenciales, claves de configuración y archivos del SO.
  • Principio de Defensa: Evitar pasar rutas de archivos directamente desde parámetros de usuario; utilizar IDs mapeados o nombres de archivo validados estrictamente.

02. Procedimiento Técnico y Uso de Burp Suite

A continuación se detalla el procedimiento paso a paso para identificar y explotar la vulnerabilidad en el entorno del laboratorio de PortSwigger:

  1. Intercepción de Petición: Se accede a la aplicación objetivo y se activa Burp Proxy Intercept al cargar una de las imágenes de los productos en la tienda.
  2. Análisis del Parámetro Vulnerable: Se observa que las imágenes son solicitadas a través de la ruta /image?filename=21.jpg.
  3. Transferencia a Repeater: Se envía la petición GET a Burp Repeater mediante la combinación Ctrl + R para realizar pruebas iterativas.
  4. Manipulación del Payload: Se modifica el valor del parámetro filename reemplazando la imagen por la secuencia de retroceso de directorio hacia el archivo sensible: ../../../etc/passwd.
  5. Análisis de la Respuesta: Se envía la petición y se verifica en la pestaña de respuesta (Response) que el servidor devuelve el contenido del archivo /etc/passwd con un código de estado HTTP 200 OK.

03. Documentación Técnica del Laboratorio

Lab: File path traversal, simple case

URL del Laboratorio: PortSwigger Web Security Academy - Simple Case

Alteración de la Petición HTTP:

-- Petición Original:
GET /image?filename=21.jpg HTTP/1.1
Host: lab-id.web-security-academy.net

-- Petición Alterada con Payload:
GET /image?filename=../../../etc/passwd HTTP/1.1
Host: lab-id.web-security-academy.net

Explicación Técnica del Payload:

Payload: ../../../etc/passwd
Cada secuencia ../ sube un nivel en el árbol de directorios desde la ubicación predeterminada del almacenamiento de imágenes (por ejemplo, /var/www/images/). Tres secuencias consecutivas conducen hasta el directorio raíz (/), permitiendo a la aplicación abrir y retornar el archivo de cuentas del sistema Linux (/etc/passwd).
